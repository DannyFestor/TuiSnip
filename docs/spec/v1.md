# TuiSnip v1 specification

## Purpose

TuiSnip is a keyboard-driven terminal application for saving, organizing, and retrieving code Snippets on macOS and Linux. It aims at the SnippetsLab workflow for people who live in a terminal, typically kept open in its own tmux window rather than started for a single lookup.

Every domain term in this document is defined in [`GLOSSARY.md`](../../GLOSSARY.md). This spec does not redefine them.

## Entities and rules

### Identity

Snippets, Fragments, Folders, and Tags each have a UUIDv7 primary key. The Root is not stored; it is the absence of a Folder.

### Snippet

- Title is required. The app trims surrounding whitespace before saving and refuses a blank title or one longer than 200 characters.
- Titles need not be unique.
- Description is optional plain text of up to 2,000 characters, stored as typed.
- A Snippet records when it was created and last updated. The Snippet pane shows both.
- A Snippet is in at most one Folder. No Folder means it is at the Root.
- A Snippet carries any number of Tags.
- A Snippet holds one or more Fragments, in order. Capture and a new Snippet start with one Fragment. Changing any Fragment updates the Snippet.

### Fragment

- The Fragment title is optional. The app trims surrounding whitespace and refuses one longer than 200 characters. A blank title means no title. Fragment titles need not be unique, and a Fragment without one is shown by its Language.
- Content may be empty and is stored exactly as given, up to 256 KiB.
- Each Fragment stores its own Language.
- A new Fragment takes its Language from its Folder's Default Language. At the Root that is `plaintext`.
- After creation, a Fragment's Language changes only when the user changes it. Moving a Snippet, or changing a Folder's Default Language, never touches existing Fragments.
- v1 does not guess Languages.

### Folder

- Name is required. The app trims surrounding whitespace and refuses a blank name or one longer than 200 characters. Names need not be unique, even among siblings.
- Folders form a strict tree. A Folder with no parent sits at the Root.
- Every Folder has a Default Language. A Folder created at the Root starts with `plaintext`. A Folder created inside another copies its parent's Default Language once, at creation. There is no live link afterwards.

### Tag

- Names are trimmed, may contain internal spaces, and may not contain commas.
- Names are case-insensitive. `Go` and `go` are one Tag, and the Tag keeps the spelling first used.
- A Tag that no Snippet carries still exists. It shows a count of 0 until the user deletes it. Adding a Tag of the same name to a Snippet reuses it.
- Renaming a Tag onto the name of an existing Tag merges the two.

### Language

- The Language picker offers every chroma lexer by default.
- Config may curate a list of Languages. When it does, the picker shows only that list, with a toggle to reveal all lexers.
- A Fragment keeps its Language even if that Language is not in the curated list.

## User flows

### Capture

1. The user triggers Capture. It uses the Browse selection: a Folder or the Root receives the Snippet, with a Tag the Snippet goes to the Root carrying that Tag, and with the Trash it goes to the Root in plain text. Saving from the Trash makes the Root the Browse selection.
2. TuiSnip reads the clipboard with the platform tool (`pbpaste`, `wl-paste --no-newline`, `xclip -out -selection clipboard`, `xsel --output --clipboard`).
3. The edit overlay opens with the clipboard content in the Fragment, the Folder's Default Language, and focus on the title.
4. Saving creates the Snippet in that Folder. Nothing is written before the first save.
5. TuiSnip refuses some clipboards up front. It opens nothing, and the status line says why:
   - An empty clipboard: "Clipboard is empty".
   - No clipboard tool installed: "No clipboard tool found (pbpaste, wl-paste, xclip, xsel)".
   - Content over the 256 KiB a Fragment holds: "Clipboard is larger than 256 KiB".
   - Content over 10,000 lines, which the textarea would cut. Lines are counted the way the edit overlay counts a paste into empty Content ([Edit overlay](ui.md#edit-overlay)), so exactly 10,000 lines open. The status line says "Clipboard is longer than 10,000 lines; use ctrl+e to edit in $EDITOR", naming the first key the user configured for `open_in_editor` in the `content` Scope (`ctrl+e` by default). With no key bound it says only "Clipboard is longer than 10,000 lines".

### Hand-write a Snippet

1. The user creates a new Snippet. Like Capture, it uses the Browse selection: a Tag sends it to the Root carrying that Tag, and the Trash sends it to the Root in plain text.
2. The edit overlay opens with an empty Fragment in the Folder's Default Language and focus on the title.
3. Content can be typed, or pasted by bracketed paste, and keeps its tabs ([Tabs in Content](ui.md#tabs-in-content)). A paste that would make Content longer than 10,000 lines is refused ([Edit overlay](ui.md#edit-overlay)).
4. Saving creates the Snippet. Nothing is written before the first save.

### Browse

1. The Folders Pane shows the Folder tree and the Tags Pane the Tag list, each entry with its Snippet count. Folders can be collapsed, and TuiSnip remembers collapsed Folders in its state file. Snippets and Folders in the Trash are left out everywhere outside the Trash list: they count neither in the Folders Pane nor in the Tags Pane and the Tag editor, a trashed Folder leaves the Folder tree and the Folder picker, and Browsing a Tag doesn't list them. The Folders Pane ends with a `▪ Trash` row counting the Trash items ([Rename and delete](#rename-and-delete)).
2. Selecting a Folder lists its Snippets. Selecting the Root lists the Snippets at the Root.
3. Selecting a Tag lists every Snippet carrying it, across all Folders, outside the Trash.
4. Folders are listed alphabetically. Snippets are listed by title by default. A key cycles the order through title, last updated, and created, the two dates newest first. Ties go to title, ignoring case. TuiSnip remembers the chosen order in its state file.

### Search

1. The user opens the Search popup over the main screen and types a query.
2. Results update on every keystroke and cover all Snippets outside the Trash, regardless of the current Browse selection. Neither a trashed Snippet nor a Snippet inside a trashed Folder shows.
3. Title, Description, Tags, and Fragment titles match fuzzily and ignore diacritics, so "cafe" finds "Café". The content of every Fragment matches as a literal substring, diacritics included. Every field matches case-insensitively unless the query contains an uppercase letter.
4. Each field's match score is weighted: title ×4, Tag ×3, Fragment title ×3, Description ×2, content ×1. A Snippet's score is its best weighted field score. The weights live in one named table.
5. Results are ordered by score. Ties go to the most recently updated Snippet, then to title.
6. An empty query lists the Snippets of the current Browse selection. With the Trash as the Browse selection, it shows no results and the line "Search doesn't cover the Trash". A query of only whitespace counts as empty.
7. A result opens on one Fragment. When the best weighted score is a Fragment's title or content, it opens on that Fragment, and on the earliest one when several Fragments tie. A Fragment that ties with the title, a Tag, or the Description still wins. Otherwise, and for an empty query, it opens on the first Fragment.
8. The popup previews the highlighted result on the Fragment it opens on. Accepting it reveals the Snippet in its Folder, focuses the Snippet pane, and keeps that Fragment as the Shown Fragment. A Copy key copies that Fragment and closes the popup.
9. There is no query syntax in v1. The whole query, spaces included, is one pattern, so "docker run" finds "docker container run" but not "run docker".

### Copy

1. The user triggers Copy on the selected Snippet. TuiSnip places the Shown Fragment's content on the clipboard. The Search popup copies the Fragment the highlighted result opens on.
2. A trailing newline is trimmed by default. Config can turn the trim off.
3. On a local session, TuiSnip writes with the platform tool (`pbcopy`, `wl-copy`, `xclip`, `xsel`). The status line says "Copied".
4. Over SSH, or when no platform tool is available, TuiSnip sends OSC 52 to the terminal. The terminal gives no confirmation, so the status line says "Sent to terminal".
5. TuiSnip stays open, unless `copy.quit_after` is set.

### Edit in the TUI

1. The Snippet pane shows the Shown Fragment highlighted, read-only, under a tab strip when the Snippet has several Fragments or its only one has a title ([Layout](ui.md#layout)).
2. The edit key opens the edit overlay over the main screen: title, Description, Tags, then the Fragments under a tab strip, with the Shown Fragment's title, Language, and a plain textarea for its content. It opens on the first Fragment. The Panes don't respond while it is open.
3. The edit overlay is the only place Fragments change. Bindings switch the Shown Fragment, add one after it in the Folder's Default Language, remove it after a [y/N] confirmation, and move it left or right. The last Fragment can't be removed: deleting the Snippet is the way. Saving writes every Fragment in the order shown, and cancelling discards every Fragment change. The rules are in [Edit overlay](ui.md#edit-overlay).
4. Tags are chosen in the Tag editor, which toggles existing Tags and creates new ones. The Language comes from the Language picker.
5. Saving or cancelling closes the overlay and shows the highlighted view. Cancelling with unsaved changes asks for [y/N] confirmation first, default No. For a new Snippet, cancelling discards it.
6. The textarea does not highlight syntax in v1.
7. The textarea cuts content at 10,000 lines, so a stored Snippet with longer content opens read-only in the overlay and is edited through the external editor. The other fields stay editable, and saving keeps the content byte for byte. The rules are in [Edit overlay](ui.md#edit-overlay).

### Edit in an external editor

1. The editor key suspends the TUI and opens one Fragment's content in an external editor: the Shown Fragment of the Snippet list, the Snippet pane, or the edit overlay.
2. The editor is the first of: config `editor`, `$VISUAL`, `$EDITOR`, then the first of `nvim`, `vim`, `vi`, `nano` found on `PATH`. It runs through `sh -c`, so the command may carry arguments ([config](config.md#editor)).
3. If none is found, the status line says "No editor found; set `editor` in config.toml". If the command can't start, the status line shows the error.
4. The content goes to a file in a fresh private temporary directory (`0700`, file `0600`, under `$TMPDIR`), named after the Language's first chroma filename pattern so the editor highlights it: `*.go` gives `snippet.go`, `Dockerfile` gives `Dockerfile`, and plain text or a Language without a pattern gives `snippet.txt`. TuiSnip removes the directory after reading the file back.
5. When the editor exits successfully, TuiSnip reads the file back into the edit overlay as an unsaved change to that Fragment, opening the overlay on it if needed. Saving is the usual save. If the content is unchanged, nothing happens and the Snippet isn't marked as changed. Tabs stay tabs ([Tabs in Content](ui.md#tabs-in-content)). Content over 10,000 lines lands read-only and saves byte for byte ([Edit overlay](ui.md#edit-overlay)).
6. If the editor exits with an error, such as `:cq` in vim, TuiSnip discards the content and the status line says "Editor exited with an error; changes discarded".

### Move

1. The move key opens the Folder picker over the main screen. The picker includes the Root.
2. A Snippet moves to the chosen Folder or the Root. Its Fragments keep their Languages.
3. A Folder moves under the chosen Folder or to the Root, taking its subtree along. The picker refuses to move a Folder into itself or any of its descendants.

### Duplicate

1. The duplicate key copies the selected Snippet into the same Folder, with the same Title, Description, and Tags, and every Fragment with its title, content, and Language, in the same order. The copy gets new ids and timestamps.

### Rename and delete

- Folders and Tags are created, renamed, and deleted in place in the Folders and Tags Panes. There is no separate management screen.
- A Tag created in the Tags Pane exists with a count of 0 until a Snippet carries it.
- Deleting a Snippet or a Folder moves it to the Trash at once, without a confirmation. The status line says `Moved Snippet "Prune everything" to the Trash` or `Moved Folder "docker" to the Trash`. A deleted Folder is one Trash item with its whole subtree. Separate deletes stay separate items: a Snippet deleted before its Folder doesn't come back when the Folder is restored.
- Snippets in the Trash keep their Tags but don't count toward them. Deleting a Tag removes it from trashed Snippets too.
- With the Trash as the Browse selection, the Snippet list is titled `Trash` and lists the Trash items, newest deleted first. A trashed Folder reads `▸ docker` with its Snippet count. The Snippet pane shows a trashed Snippet read-only, or a trashed Folder's name, counts, and subtree outline, each with the path it was in and the day it was deleted. A trashed Folder's counts and outline leave out the Snippets and subfolders inside it that are separate Trash items. An empty Trash shows "The Trash is empty."
- Restoring a Trash item puts it back into its Folder, or a Folder back under its parent, when that is still outside the Trash, and a Folder comes back with its whole subtree. Otherwise it goes to the Root. The status line says `Restored "Prune everything" to go / testing`, or `Restored "Prune everything" to the Root` for an item that was at the Root. An item that falls back to the Root says why: `Restored "Prune everything" to the Root; its Folder is in the Trash` (`…; its Folder was deleted`) for a Snippet, and `Restored "docker" to the Root; its parent Folder is in the Trash` (`…; its parent Folder was deleted`) for a Folder.
- The Trash empties only when the user says so, and never on a timer. Deleting a Trash item permanently asks for [y/N] confirmation, default No: `Permanently delete Snippet "Prune everything"? This cannot be undone. [y/N]`, or for a Folder, counting its subtree: `Permanently delete Folder "docker", 1 subfolder, and 15 Snippets? This cannot be undone. [y/N]`. A Folder's subtree goes with it, but a Snippet or subfolder inside it that is a separate Trash item stays in the Trash, at the Root, remembering the path it was in. Restoring it later puts it at the Root: `…; its Folder was deleted`.
- Emptying the Trash asks for [y/N] confirmation, default No, counting everything inside trashed Folders, with "1 Folder" or "1 Snippet" for one and a zero count left out: `Permanently delete 3 Folders and 20 Snippets in the Trash? This cannot be undone. [y/N]`. It deletes only the Trash items the confirmation counted, so an item moved to the Trash while it was open stays. The status line says what was deleted, which can be fewer than the confirmation counted: `Emptied the Trash: 2 Folders, 20 Snippets`.
- Permanent deletion never deletes Tags.
- Deleting a Tag removes it from every Snippet that carries it. If any Snippet carries it, TuiSnip asks for [y/N] confirmation stating the count, for example: `Permanently delete Tag "go" and remove it from 4 Snippets? This cannot be undone. [y/N]`. Default No. A Tag with a count of 0 is deleted without asking.

### Quit

- Quitting while the edit overlay has unsaved changes asks for [y/N] confirmation, default No.

### Concurrent instances

- Several TuiSnip instances may run against the same database at once.
- A save carries the last-updated time it loaded. If the Snippet changed elsewhere since, TuiSnip refuses the save and offers to reload.
- When a Snippet or Folder action finds its Snippet or Folder moved to the Trash or deleted elsewhere, the status line says `Snippet "Prune everything" was moved to the Trash or deleted in another TuiSnip` (or `Folder "docker" …`), and TuiSnip reloads the Folders, the Tags, and the Snippet list. This covers move, rename, New Folder under the Folder, set Default Language, duplicate, Copy, and moving it to the Trash. When a Snippet or Folder is moved into a Folder that is gone, the message names that Folder. Tag actions keep the generic failure text.
- Moving an item to the Trash only applies to an item outside the Trash. Writes that place into a Folder (Move Snippet, Move Folder, New Folder, New Snippet, Capture, Duplicate) check that the Folder is outside the Trash.
- Restore, delete permanently, empty, and Copy in the Trash act only on items still in the Trash. Emptying skips the counted items that left it. Otherwise the status line says `"Prune everything" is no longer in the Trash`, and TuiSnip reloads the Folders and the Trash list.
- Instances do not refresh each other live. The Trash count and the Trash list refresh at start-up, after this instance's own writes, when the Trash becomes the Browse selection, and after one of the failures above.

### Start-up

- If no config file exists, TuiSnip writes one with every default filled in. This happens on any start, not only the first, so deleting the file restores the defaults.
- If no database exists, TuiSnip creates it. It runs pending migrations on every start. There is no seed data.
- Before migrating an existing database, TuiSnip backs it up and keeps the latest 3 backups. If the backup fails, TuiSnip refuses to start.
- If the database was created by a newer TuiSnip, TuiSnip refuses to start and asks to be upgraded.
- An empty main screen shows a hint listing the main Bindings.

## Screens and overlays

TuiSnip has one main screen with four Panes: Folders above Tags in the left column, the Snippet list, and the Snippet pane.

Overlays on top of the main screen:

- Search popup, with a preview of the highlighted result
- Edit overlay, covering most of the screen
- Language picker
- Folder picker, for moving
- Tag editor, showing each Tag's Snippet count
- Confirmation dialog
- Help, listing the active Bindings

Behaviour across the main screen:

- One key zooms the focused Pane to fill the screen. Pressing it again restores the layout. Focus still moves between Panes while zoomed. Zoom is not remembered across restarts.
- The status line shows the focused Scope's main Bindings.
- The mouse focuses Panes, selects rows, and scrolls, unless config turns it off.
- The Snippet pane shows line numbers and has a wrap toggle.
- The theme follows the terminal background, light or dark, and config can force either. v1 ships one light and one dark colour scheme.

Layout, proportions, navigation, the overlays, and the mouse are specified in [the UI spec](ui.md).

## Configuration

Config is a hand-edited TOML file in the XDG config directory. The app writes it only to create it with defaults when it is missing, and never modifies an existing file. Remembered state, such as sort order, lives in a separate state file that the app owns. An invalid config stops start-up with every error listed.

Config keys in v1:

- `editor`
- `theme`: `auto`, `light`, or `dark`
- `languages`, the curated Language list
- `copy.clipboard`: `auto`, `native`, or `osc52`
- `copy.trim_trailing_newline`
- `copy.quit_after`
- `mouse`
- `bindings.<scope>.<name>`, the keys for every Binding

The schema, defaults, validation, Binding format, and state file are in [config](config.md).

## Command line

- `tuisnip` starts the TUI.
- `tuisnip --version` prints the version.
- `tuisnip --paths` prints the config, data, backup, state, and log paths.
- `tuisnip export <file>` writes the whole Library to `<file>` as JSON, in the [Export format](export.md). It overwrites an existing file without asking, but writes it atomically, so a failed Export never replaces a good backup. The Library it writes includes the Trash. It prints the path and the number of Folders, Tags, and Snippets written, the Trash included. When the Trash isn't empty, a second line counts what it holds, everything inside a trashed Folder included, with a zero count left out: `In the Trash: 1 Folder, 3 Snippets`, or `In the Trash: 2 Snippets`. The file's directory must already exist. Like `tuisnip`, it loads `config.toml` and opens the database first, creating either when it's missing, and an invalid config stops it.
- `tuisnip import <file>` reads a TuiSnip Export and adds every Folder, Tag, and Snippet in it, keeping their IDs and dates. It gives back the same Trash: the same Trash items, in the same order, with the same restore destinations. An Export from before the Trash (format version 1) imports with an empty Trash. It runs only when the Library is empty, and the Trash counts: if any Snippets, Folders, or Tags exist, Trash items included, it refuses and says to move the database aside first (`tuisnip --paths` shows where it is). It checks every record the way the TUI does (limits, unknown Languages, updated before created, deleted before created), a Trash item like any other, and also refuses Folder cycles and references to a missing Folder or Tag. One bad record fails the whole Import, nothing is written, and the error names each bad record. A file from a newer TuiSnip is refused with a request to upgrade. It prints the number of Folders, Tags, and Snippets created, the Trash included, and the same `In the Trash` line as `export` when the Trash isn't empty. Like `export`, it loads `config.toml` and opens the database first.
- `tuisnip import --from snippetslab <file>` reads a SnippetsLab JSON export (Library > Export > JSON Document) and adds its live Snippets, its Folders, and its Tags beside what the Library already holds, with fresh IDs. The source is stated, never guessed from the file.
  - Snippets in SnippetsLab's Trash are skipped. The Folder tree comes over as it is, even where a Folder of the same name exists. A Folder without a Default Language takes its parent's, or plain text at the top. A Tag whose name a stored Tag already has, ignoring case, is merged into the stored Tag, which keeps its spelling. A Snippet whose Folder or Tag the file lacks goes to the Root, or loses that Tag. Running it twice gives two copies.
  - Fragments keep their order, and a Fragment title that is exactly `Fragment` (SnippetsLab's default) is dropped. Fragment notes become the Description: one note as it is, several joined in Fragment order, each under a line naming its Fragment by its title or, without one, its Language. Formatting is dropped, and a link becomes `text (url)`, or only the URL when the two match.
  - A fixed table maps the Pygments lexers SnippetsLab stores to Languages. A lexer outside it falls back to plain text.
  - Created and modified dates are kept. A Snippet's updated date is the latest of its own and its Fragments'. Folders and Tags, which SnippetsLab doesn't date, are dated at the Import.
  - Every record is checked the way the TUI does. One bad record fails the whole Import, nothing is written, and the error names each bad record by its SnippetsLab UUID, and a Fragment by its position.
  - It prints the number of Folders, Tags, Snippets, and Fragments created, the number of Trash Snippets skipped, the Snippets that lost a pin, a Gist link, or an attachment, and every Folder and Fragment whose lexer fell back to plain text.

An unknown subcommand, a subcommand with the wrong number of arguments, `-` as an argument, or `--version` or `--paths` together with a subcommand prints usage to stderr and exits 2. Any other failure prints the error to stderr and exits 1. Reports go to stdout.

CLI subcommands such as `get` and `add` are on the roadmap.

## Platforms

- macOS and Linux, on amd64 and arm64. Linux covers both X11 and Wayland.
- The same XDG paths apply on both platforms.
- Running over SSH is supported, best-effort, through OSC 52. The README tells tmux users to `set -g set-clipboard on` for that path.

## Non-goals for v1

- Windows support
- Sync between machines, database encryption, telemetry, i18n
- Snippet version history, templates with placeholders, a recently-used list
- Undo. Deleting moves Snippets and Folders to the Trash, and the Trash restores them.
- Language guessing
- Everything in [`ROADMAP.md`](../../ROADMAP.md)
